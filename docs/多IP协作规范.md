## 一、IP 隔离原则（2026-10-27 修正）

**两个 IP 是两套完全独立的生产线，各自在自己的工作区里，不共享任何东西。**

| IP | 工作区目录 | 空间 | 建档体系 | 技术差异 |
|---|---|---|---|---|
| 陈洁斌主号 | `/home/qmr/github/ai-video-studio/profiles/陈洁斌主号` | 洁斌资产 | ✅ 本体系 | 竖屏 1.26MP 864×1536，重叠 **5**（2026-10-27 由 22 改） |
| 珠珠·雅太社 | `/cfu/雅太社AI视频` | 雅太社AI视频 | ⛔ 独立 | 横竖双形态，重叠 **5**，二采 lms_v0.1 |

> ⚠️ 重叠帧现在两家都是 5，**但这不代表可以共用脚本**。采样器、二采模型、
> 画幅、静音阈值仍全部不同，共用必然串参数。

⚠️ **不要再在洁斌的工作区下建珠珠目录**。曾于 2026-10-27 误建
`洁斌资产/珠珠雅太社/`（复制了洁斌的 22 帧重叠参数到珠珠身上），已删除。
珠珠的资产一律进 `/cfu/雅太社AI视频/`。

### 为什么不做「一套脚本 + 参数切换」
不只是参数不同，**技术路线已经分叉**：

- 重叠帧：两家都是 5（雅太社 2026-10-23 圈图定板；洁斌 2026-10-27 用户指定，原 22）
- 采样器：`MiniMaxH3FiniteSegmentSampler` / `MiniMaxH3FiniteSegmentVideoSampler`
- 二采模型：`h3_upscaler_lms_v0.1` / `minimax_h3_latent_upscaler_3d_fp16_V2`
- 画幅：横竖双形态 / 纯竖屏
- 品牌口径：面料红线+情绪红线 / 人设圣经

共用一套脚本 = 每天在两套参数间切换，迟早串参数。**各存一份，各改各的。**

### 跨 IP 参考的正确做法
只借**算法**，参数一律按本 IP 重算，并在文档写明差异：

```
## 字幕流程
参考 /home/qmr/github/ai-video-studio/profiles/陈洁斌主号/03_生产脚本/make_srt_asr.py 的算法，
但参数必须按雅太社重算：
- 静音阈值 0.06（洁斌 0.12，雅太社气口更短）
- 一行 22 字（洁斌竖屏 12 字）
- 字号 66px 横屏 / 88px 竖屏（洁斌 52）
```

❌ 错误做法：`cp` 脚本过来直接用（参数会带着上一家的）。
✅ 正确做法：读算法 → 在本 IP 重写关键常量 → 用已知坏片回归验证。

## 一之二、建档体系三件套（2026-10-28 建立）

| 文件 | 位置 | 作用 |
|---|---|---|
| `registry.json` | `/home/qmr/github/ai-video-studio/` | 总册。`ips` 登本体系 IP（含别名），`excluded` 登独立体系及原因 |
| `newip.py` | 每个 IP 的 `03_生产脚本/` | 接新客户：查总档 → 防重名 → 建 01~08 树 → 生成 ip.json → 登记进总册 |
| `ip_guard.py` | 每个 IP 的 `03_生产脚本/` | 出片前自检：素材缺失/null 一律拒绝，**绝不退回别的 IP 顶替** |

**接一个新客户的标准动作**：

```bash
cd /home/qmr/github/ai-video-studio/profiles/陈洁斌主号/03_生产脚本
python newip.py --name 某某品牌 --tag M --space 某某资产 --aliases "老王,王总"
#   → 建 01~08 目录树 + 生成 ip.json（素材字段全是 null）
#   → 之后：录 8 秒人声 / 写逐字稿 / 定起始静帧 → 填进 ip.json 的三处 null
python /home/qmr/github/ai-video-studio/profiles/某某品牌/03_生产脚本/ip_guard.py
#   exit=0 才能出片；exit=1 会明确列出缺哪几项
```

> 💡 2026-10-28 起更推荐用 CLI 一站式建档（少踩坑，见 `RUNBOOK.md`）：
> ```bash
> python3 bin/vstudio.py card-new --name 某某品牌 --type 客户 --tag M \
>         --role "本地生活口播·竖屏" --aliases "老王,王总"
> python3 bin/vstudio.py guard 老王
> ```
> `vstudio.py` 会强制 `IP_REGISTRY` 指向项目册、堵死 `newip.py` 的交互式 stdin，
> 并在册子里自己兜底登记——直接调 `newip.py` 不会有这些保护。

> ⚠️ `--aliases` 不是可选项。
> 用户口头叫的常常是人名（"老王那条片子"），而目录名是品牌名。
> 没有别名，按口头名字搜不到已有工作区 → 又建一个重复目录（2026-10-27 踩过）。

**为什么不再扫 /cfu 全盘查重**（旧版 newip.py 的做法，已废弃）：
全盘扫描会把独立体系（雅太社）也当成「本体系的 IP」报出来，
进而诱导我把建档文件放进别人的工作区 —— 2026-10-27 真的这么做了。
现在改成**总册登记制**：册子里的才是本体系的，册子外的单独标 `excluded`，
两者分开报、分开处置（一个是"别新建，去改那份"，一个是"别碰"）。

## 二、开工前必检三件（顺序不能变）

> ✅ 其中 **1、2 两项已被 `ip_guard` 自动接管**：生产脚本启动即打印
> IP / 音色参考 / 静帧，素材缺失直接 exit，不会静默退回上一家的素材。
> 下面的人工核对是**第二道防线**，用来防 ip_guard 也看不出的情况
> （比如档案填的是本 IP 的文件，但那文件本身就是从别家复制来的）。

### 1. 确认自己在哪个 IP 的目录里
```bash
pwd      # 必须是 /home/qmr/github/ai-video-studio/profiles/<IP名>/03_生产脚本
```
⚠️ 在错误的目录里跑脚本，`02_素材真值` 会指向错的 IP。

### 2. 确认音色和静帧
脚本每次启动都会打印，**必须逐字核对**：

```
音色参考 洁斌_声音参考_8s.flac   逐字稿「我给你看个真的...」
静帧 陈洁斌_主号_静帧_C方案_881204203.png
```

这两行是唯一护栏。看到不属于本 IP 的名字，**立刻停下**，不要继续。

### 3. 确认输出目录
`TAG` 前缀决定落盘位置。新 IP 用新的套次编号（如珠珠从 `Z01` 起）。

## 三、换 IP 时的环境变量清单

| 变量 | 作用 | 不换的后果 |
|---|---|---|
| `REF_SRC` | 声音参考 flac | **用上个 IP 的音色**（最严重） |
| `REF_TEXT` | 参考音逐字稿 | 音色克隆跑偏 |
| `STILL` | 起始静帧 png | **长上个 IP 的脸**（最严重） |
| `INSTR` | TTS 语气指令 | 语气与人设不符 |
| `TAG` | 套次前缀 | 输出覆盖到别的 IP |

## 四、云端算力接入（待落地）

### 现状判断
- 本机 4080S 16GB 跑 2.0MP 需要 13 段 12 接缝，**不建议**
- 云端候选：OneThingAI（按分钟计费）/ AI Gate（按天 / 包月）

### ⚠️ 最大的坑：云端镜像的模型不是本机定版
AI Gate「小黄瓜 ComfyUI 最新镜像」声明的 H3 模型是
`minimax_h3_f1v_lightx2v_turbo_4step_v1.0_768p_...`（**768p / 4 步 / lightx2v**），
本机定版是 `minimax_h3_fused_refdelta_r1024_turbo8_mystic07_int8_convrot`（**8 步**）。

**不是同一个模型 → 出片肤色、锐度、运镜风格都会变。**
跨 IP 系列片最致命的是一致性，所以**用云端前必须先做同提示词 A/B**，
确认风格可接受再批量。

### 自建云的模型上传量
H3 全套依赖约 **42 GB**：
- UNET `minimax_h3_fused_refdelta_r1024_turbo8_mystic07_int8_convrot` 20.98 GB
- CLIP `qwen3vl_32b_minimax_h3_nvfp4_awq` 15.69 GB
- video VAE `minimax_h3_video_vae_fp16` 4.9 GB
- audio VAE `minimax_h3_audio_vae_fp32` 0.578 GB

首次上传是主要成本，之后持久化在云盘即可。

## 五、夜间自动执行的前提

自动跑之前必须先有「无人在场也能发现出错」的手段，否则第二天醒来是一堆废片。

最低要求：
1. `DRY=1` 先跑一遍分段校验，通过才允许提交
2. 每段完成后落盘 `Sxx_进度.json`（段号 / 起止帧 / 耗时 / 状态）
3. 任一 OOM 或校验失败 → **停止整批**，不继续烧后面的段
4. 全部完成后自动跑 `seam_check` + `skin_timeline`，把结果写进 `Sxx_制作记录.md`
5. 失败时留 `Sxx_失败.log`，含最后一次成功的段号

## 六、对话对接方式（上下文成本）

| 方式 | 上下文 | 适合 |
|---|---|---|
| **同一对话连续做多套** | 越用越贵，前几套的细节全在 | ❌ 不建议 |
| **每套一个新对话** | 每次从零加载 `MEMORY.md`（4.5KB）+ 参考手册（按需） | ✅ **推荐** |

**推荐做法**：一套片子一个对话。开工第一句给我三行：
```

需求: 第 3 套，讲配货清单，45 秒

```

这样每套的上下文消耗基本恒定，不会随套数增长。
