新手使用手册

ai-video-studio · 从开机到出第一支片 · 照着做就行
一句话：这是什么

这是一套「AI 数字人口播视频」的生产线。你给它一段文案，它出一条竖屏口播片 （配音 + 字幕 + 画面 + BGM）。客户多了也不乱 —— 每个人一份独立档案。

一、先记住：东西分两个地方

这是最容易搞混的一件事，搞清楚了后面全顺。

改什么动哪里影响面
引擎升级（模型/字幕/路由）bin/ orchestration/ captions/ config/所有 IP 受益，档案一字不改
个人档案（音色/静帧/参数）/cfu/ai视频档案库/<IP>/只影响这个人，引擎不动

二、开机（每天第一件事）

第 1 步起网页工作台
bash bin/start-ui.sh
第 2 步看它打印的真实地址
端口会自动顺延，别猜
第 3 步开工自检
python3 bin/vstudio.py guard 洁斌

自检会告诉你：参数齐不齐、服务活着没、缺什么素材。自检不过就别出片 —— 不然十几分钟 GPU 白烧。

三、接一个新客户

点界面上「新建档案卡」，跟它说人话就行，比如：

客户是开潮汕牛肉火锅的，馆子叫八合里，老板姓林，四十多岁，
不愿意上镜，想让我用 AI 给他做个口播号，一周三条，
发抖音和小红书，主要讲牛肉怎么挑、火锅怎么涮，
别讲加盟别讲价格，他说话有潮汕口音，语速慢点

AI 会整理成字段，顺手写人设文档。建档时可以同时传素材：

传什么AI 怎么处理
人像参考图看图写外貌真值（性别/年龄段/脸型/发型/穿着/气质）
音色音频实测基频 / 语速 / 响度 / 静音占比
其它介绍文字直接并入上下文
关于音色：这里不「听」，只测

路由里目前没有音频输入通道（只有文本和图片）。硬让模型描述音色，它只能编一段 听起来很像的假话 —— 而后面 TTS 会照着这段假描述去克隆，等于给真人安一个 不存在的嗓音。这比不给更糟。

所以做法是用 ffmpeg 量出客观物理量，再让 LLM 把数值翻译成一句人话。

四、出一支片（六步，顺序别乱）

四之二、试片（可选，默认不开）

正式出片前想先看看「这个人长什么样 / 这段动起来是什么感觉」，用试片台：

模式怎么跑
手动每一步都要你点一下，过审了才走下一步
从此处起跑完后面从某一步开始，后面自动跑完
一条龙全自动从头跑到尾，中间不停
默认是「手动 + 都不启用」

定帧和样片都默认关闭 —— 不是每一轮都需要，需要的时候再打开。 想先确认形象就开定帧，想看动态感觉就开样片。

四之三、定帧素材：三条路挑一条

最难的一步不是「生成」，是写那段英文。所以给了三条路：

路什么时候用要注意
中文描述 → AI 写手上只有中文：「五十多岁的面馆老板，短发花白，深蓝围裙」 AI 补出来的细节（比如它猜了戴不戴眼镜）会列给你，一定要核
润色现有英文已经有一段提示词，只想改得更稳 身份特征不会被动到，改的是光线 / 机位 / 质感
引用已有素材手上已经有客户照片或以前跑出来的静帧 只改 ip.json 的指针，原图不动；登记错了改回来就行

四之四、配乐：五条路，默认走「复用」（不再每次重新生成）

一句话：配乐生成一次就够了。

任何一条路生成完，那首曲子都会自动沉淀进 <IP>/02_素材真值/配乐/（带来源/种子/时长）， 之后把来源切成 复用已有 挑一首即可 —— 0.5 秒出结果，不占显卡， 原来是几分钟。
在「声音 · 配音与配乐」面板里能直接试听、点「用这首」， 选完写进 ip.json 的 bgm.source=reuse + bgm.pick=<文件名子串>，以后每次出片都拿这首。

路优点代价
reuse 复用已有 ★推荐0.5 秒、不占显卡、风格稳定（系列片听感统一）库里得先有一首
synth 本地合成几秒出、不占显卡、每次一样永远同一首 88 BPM
comfy ComfyUI 生成本机 MiniMax-Music-3 三件套齐全，按描述生乐占显存约 10G，一次几分钟
library 本地曲库用你已买断 / 已有的曲子，可随机换要先在 bgm.library_dir 填目录
online 在线曲库Jamendo / Freesound 有 API要申请 key（界面不给填密钥，防止泄漏）
别指望 Pexels 和 Pixabay 拿音乐

这两家的 API 只有图片和视频，没有音乐端点（实测 Pexels 的 /v1/music 之类全是 404）。 网页上能下音乐，但 API 走不通。

四之四之二、客户给了新素材：怎么引用、每段能不能用不同的

素材分两级，别混。
级别放哪管什么
IP 级02_素材真值/ 根下这个人长什么样：形象底图、起始静帧、8 秒声音参考
套次级02_素材真值/<套次号>/这条片子专用：门店照、产品照、客户现场照

界面：「创作」标签 → 本套素材 · 每段用哪张。上传 → 文件进套次目录、 清单写 05_文案/<套次>/materials.json。 没建这份清单时，整片只用起始静帧那一张，跟以前完全一样。

不同分段用不同素材：能，而且是原生的

H3 每段最多吃 9 张参考图；分段生成时插件会按该段的图片列表重新筛一遍， 并从 1 重新编号 <Picture N>。 所以：段 2 勾上门店照，出片提示词骨架一个字都不用改， 那句 <Picture 1> 在第 2 段自动指到门店照。

已实测：同一条音频、同一个种子，只把第 2 段的参考图换成另一位老者， 第 2 段出来就是他，其他段还是本人。

⚠ 换了素材，服装和背景不会跟着换

实测里第 2 段的脸换成了新素材的人，但身上还是提示词描述的「白色对襟衫 + 领夹麦」、 背景还是原来那间屋子。因为服装/场景是写在提示词骨架里的具体描述，描述压过参考图。
要让服装背景也跟着变，得同时改 ip.json 的 video.prompt_vars，或那一段的 prompts.en.json —— 光换图不够。

三个会被拦下来的写法

① 某段挂了超过 9 张 → 直接报错（不拦的话 H3 会静默丢掉多余的，你以为用了其实没用）
② 引用了清单里不存在的 id → 报错，并列出已登记的有哪些
③ 素材路径跑出本 IP 目录 → 报错。禁止跨 IP 引用，否则会把上一位客户的脸串给下一位。

四之四之三、参考视频：换人 / 换服装 / 换文案分别怎么接

客户经常甩过来一段视频：「照这个拍一条」「这个运镜我要」「能不能把里面的人换成我」。 这类需求走的不是参考图那条路，是 videoClips（参考视频）。 界面同一块面板：上传参考视频 → 登记 → 在「每段用哪张（图 / 视频）」里勾选哪几段用它。

用途只有三档，选错档后果很具体
档位什么时候用选错的后果
可编辑参考（edit）
referenceMode=edit		 换人、换服装、换风格、只要那个场面和运镜 默认档。不锁原人物 —— 配着你自己的静帧，出来就是你
固定参考（guide）
referenceMode=guide		 原样续写、要保持原视频的运动 会把原视频里的人一起锁住，换不了人
只锁首尾（boundary） 只要开头结尾对得上，中间随便演 中间会自由发挥
换人 / 换服装：两步都要做，缺一步不出来

① 参考视频用途选 可编辑参考；
② 把你自己的静帧勾到那一段上，并在提示词里写他的外貌 / 服装。
只有①没有②＝模型没有「你是谁」的依据，出来的还是参考视频里那个人； 只有②没有①＝跟普通出片没区别。
⚠ 跟换参考图那条一样：服装和背景写在提示词里，描述压过参考素材。 换了人但衣服没换，去改 ip.json 的 video.prompt_vars 或那一段的 prompts.en.json。

换文案：不用动参考视频

改文案 → 重配音 → 分段时长会变 —— 参考视频的时间窗是跟着段走的 （段多长它就多长），所以自动跟着变，不用手动对齐。
要换参考视频里的哪一段内容，用「从第 N 秒开始取」（trimStart）。

三条硬上限（插件源码里的常量，超了是静默丢，不报错）

① 每段最多 3 段参考视频
② 视频参考总时长不超过 15 秒 —— 上传时浏览器会先量一遍，超了会提醒
③ 图 + 视频 + 音频合计最多 12 个
界面都会拦下来并说清是哪一条；没拦的话你会看到画面跟你给的不一样，却查不出为什么。

四之五、配音（TTS）：重抽最多的一步，单独给了面板

配音不对就得重来，来回最多次。面板最上面先摆着「这套要念的文案」 —— 跟需求台「本套文案」是同一个文件，能看字数、约几秒、上次改的时间， 点「展开全文」看全篇，点「去改文案」直接跳回需求台。

为什么把文案摆在这里

以前声音面板只有音色指令，稿子在隔壁需求台。人写完文案切过来配音，看到空的一块， 第一反应是「文案是不是被刷新了 / 不知道放哪了」——其实它好端端在同一个 txt 里， 只是这个面板没显示。现在点重做之前一定能先看到要念什么。
在需求台手改文案点「存文案」，这块会跟着一起刷新，不用手动切来切去。

这套还没文案时，卡片会变黄提示「还没有文案」。这时点重做配音会被拦下， 并带你去需求台写稿 —— 没稿子就配音，出来是空的，白发一次显卡。

两个「重做」按钮，区别只在跑到哪
  • 只重做配音：跑到「留白」就停，不重出画面 —— 几十秒、不烧显卡出图，最常用。 改了语气、或稿子改了几句想重听，用这个。
  • 从配音起，后面全重做：从配音一路重出画面、字幕到验收 —— 要烧十几分钟显卡。稿子大改、画面也要跟着变，才用它。

点之前先看清楚会跑到哪，别为了改一句话白烧二十分钟显卡。 点重做时会自动先把语气指令存进 ip.json（直接改文件不点存不会触发重抽）。

四之六、总沟通对话区：像跟我聊天一样下需求

中栏最下面那块「总沟通对话区」。不用记命令，直接说人话： 「把老王的音色改成温和一点」「给陈洁斌加条红线：不许出现同行品牌」 「新建一个客户档案卡」。

能引用素材：输入框里打 @

打 @ 会弹出本套的图片、参考视频和 IP 素材候选， 上下键选、回车插入，变成 @[01_门店.png] 这样的引用。
然后就能问「@[01_门店.png] 这张适合放第几段」—— 它会看着素材的标签和当前 分配情况回答你，不会擅自改；你明确说「放到第 2 段」，它才给你一个待确认的动作。

确认闭环：说「确认」就执行，说「算了」就取消

涉及改动，它先回一句「⏸ 将做什么 —— 需要您确认」，并把要做的动作原样记着。 你说「确认 / 直接改」就执行，说「算了 / 取消」就丢掉。

以前这里有个坑：待确认的动作没存，你说「确认」时它重新理解一遍， 很可能理解成别的事，确认就落空了。现在动作原样回传执行，不再猜。

一次说一件最准。想「确认」的同时又提新需求，分两句说更稳 —— 短句纯确认走快速通道（不花模型调用费），长句会带着上下文重新理解。

⚠ 对话不会存到磁盘

对话只在当前页面会话内按 IP 记着：切客户不串台、切回来还在， 但刷新页面就清。这是刻意的 —— 对话里常有客户原话、稿子、人设， 落本地持久化就多留一份明文。清空对话也有二次确认，会先告诉你丢的是什么。

四之六之二、批量出片：给个数字，要几条出几条

一个 IP 一次性出好几条片子，用顶栏「批量出片」。它是排队不是并发 —— 这台机器只有一块显卡，并行只会撞内存被内核杀，所以一条接一条出，结束给一份汇总报告 （在 08_过程/batch-*.json）。

选题可以留空 —— 填「要几条」就行

两种填法，二选一：

  • 手填选题：在选题框里一行写一条，逐条让 AI 写文案 + 出片。
  • 留空 + 填数字：选题框空着，在「要几条」里填个数字（1–20）， AI 会按这个号的人设自动出 N 条选题，再逐条写文案、出片。要几条填几条。

两个都空会拦下来，不让你提交一个空队列干等。 勾「先看计划」可以只列出要跑哪几条、不真烧显卡（自动出题那步会花一次选题调用， 出片不跑）。

一次别贪多

一条片子正式档要十几二十分钟，填 20 就是连着跑好几个小时。 建议先填 2–3 条试，勾「先看计划」确认题目和档位对了，再放开跑。 自动出题必须先读人设 —— 人设材料为空会直接拒绝，不会瞎编一批题目去烧显卡。

四之七、自动学习闭环：项目怎么记住踩过的坑

四步，前三步自动、最后一步要你点头
步骤谁做说明
① 记自动你点「重跑 / 重录 / 退回」时问一句为什么，原因落进 08_过程/_学习.jsonl（只增不改的流水）
② 提炼你点一下攒够 3 条，对话区顶部会亮「可以提炼成习惯了」。 模型把同类返工归纳成几句正向做法，出一份建议草案 _习惯建议.json
③ 采纳你确认勾几条 → 二次确认 → 写进 card.json 的 habits。改前备份、留 changelog
④ 用自动以后出选题 / 写文案 / 写提示词，习惯和近期教训一起塞进 context，模型主动避开这些坑
为什么不让它全自动写进档案卡

card.json 是业务真值，动它要二次确认 + 留痕。 模型归纳的东西会重复、会说错 —— 只配当建议躺着，等人点头才进真值。 这跟「返工记录用流水文件、不直接改档案卡」是同一条道理。

命令行也能跑：python3 bin/learning.py promote <IP> 出建议、 ... apply <IP> --items "习惯一" "习惯二" 采纳。

安全动作 vs 重活：界面上能直接跑的是安全的（重建索引、开新套次、记笔记）； 出片这类要调模型/显卡的重活，界面只给命令，你复制回终端跑 —— 不是做不到，是刻意不代跑：看不见它死在哪，比慢更可怕。

六、七个最常见的坑

1. 改了中文提示词，画面没变

出片只认 prompts.en.json。中文稿只是给人看的。 改完必须点「按现在的中文稿重新译」，否则画面用的还是旧的英文分镜 —— 这是最难查的一类假片。

2. 提示词里混进汉字，被烧成字幕

模型把提示词里的汉字理解成「画面上该出现的字」。S04 那版就是这么烧上去一整行的。 翻译前后都会过红线校验，含汉字直接整批不落盘（宁可留着旧版，不写半成品）。

3. 新卡看起来「功能全是坏的」

客户卡默认禁止上云（保护客户商业信息），所以 AI 选题/写文案需要本机模型能跑。 本人 IP 默认允许。要改去卡里的 card.json → policy.allow_cloud_llm。

4. 写了文案，别的地方看着还是老的

文案落盘只有一份：05_文案/<套次>/<套次号>_字幕文本.txt。 「需求台」面板下半截现在有一块 本套文案，显示的就是这个文件里的真实内容， 带字数、预估时长、最后修改时间 —— 你看到的和出片念的是同一份。

三个动作的区别，别搞混：

  • 存文案 —— 只改稿子，不给画面
  • 按文案生成提示词 —— 把稿子切成逐段分镜（提示词是快照，改了稿子要重切）
  • 译成英文 —— 出片只认 prompts.en.json，不译就不进片

目录里若出现两份稿子（旧版命名 目录全名_字幕文本.txt）， 出片只认短名那份；下次保存会自动把旧的那份改名留档，不会删。

5. 音色描述是「量」出来的，不是猜的

没有音频输入通道的模型说得出「低沉有磁性」，但它没在听 —— 那是编的。 项目现在的做法是先用 ffmpeg 量 F0 / 响度 / 静音占比，再让模型把数值翻成人话； 真要让模型听音色质感，得装 llama.cpp 跑本机已有的 Qwen2.5-Omni。 细节见 docs/音色识别方案.md。

6. 出片跑到一半失败，前面白跑了吗

没白跑。流水线是「按产物断点续跑」的：每一步做完都会在 07_成片/<套次>/ 留下文件，下次开跑时先看产物在不在、 比上游新不新 —— 在就不重做。所以失败后接着跑只重做失败那一步。

失败了看运行面板底部，会直接写明：

  • 停在第几步（例如 video）
  • 前面几步的产物还在（可以复用）
  • 按钮会变成 「从 video 接着跑」 —— 点它就行，不要重新点「出片」

但有一个例外，必须说清楚：H3 出片是一次提交整片 （segmentConfig.count=N，靠 previous_latent 保证段间连贯）， ComfyUI 只在最后落一个完整 mp4。所以 video 这一步内部失败，盘上什么都没有， 只能整段重出。想做成「段级续跑」就得拆成 N 次单段提交 —— 那样段与段之间的连贯性会掉，画面会跳，不值得。

7. 人设到底在哪、会不会被新内容盖掉

人设只有一处真源：档案库/<IP>/01_人设与规范/ 里的 md。 面板上显示「N 篇人设 + M 篇参考」—— 加粗的是人设主干 （文件名带「圣经」的优先，其次「人设」），其余是背景参考资料。

存的时候分两种，界面上是两个不同的按钮：

  • 存这一篇（替换） —— 落到你正打开的那一篇，覆盖前自动备份 （.bak.时间戳，只留最近 5 份，更早的进 _旧备份/）
  • 另存为新一篇 —— 另起一份，绝不碰任何人

如果不指定也照样安全：后端会自动落到人设主干那一篇，不会另造一份 人设圣经.md 去跟原有的圣经抢话。 （同一个 IP 有两份互相矛盾的人设时，AI 是整目录拼起来读的 —— 它会各信一半，写出来四不像，比没有人设更糟。）

改完人设不用重跑任何东西，下一次写稿/选题就生效。
