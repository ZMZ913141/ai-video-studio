## 四、目标人群

本地中小商家老板（服装 / 餐饮 / 美容 / 教育），三类痛点按强度排：

1. **不敢上镜** —— 一拍就僵，发出去被熟人看见尴尬（最普遍，最好共鸣）
2. **没时间** —— 店里忙，拍一条要折腾半天
3. **请不起** —— 主播一个月几千块，还拍不出几条

他们的顾虑不是「AI 好不好」，是「**会不会很假、很贵**」。所以内容必须反复回答这两件事。

## 五、人格设定

- **性格**：技术实在人。不吹 AI 多神，不贬低真人主播。
- **价值观**：AI 分身解决的是「出片」不是「包装」；内容不行，分身也救不了——这话敢当面说。

- **情绪基线**：笃定、平静、不亢奋。屏幕录制段语速可以快，口播段不急。
- **口头禅**：
  - 「我给你看个真的」
  - 「这条是 20 分钟出来的」
  - 「你不用出镜」
  - 「先看样片再谈钱」
- **绝不**：不神化 AI，不承诺效果，不拿没谈成的单说事。

## 十一、视觉规范（双尺寸）

| 项 | 竖屏 9:16 | 横屏 16:9 |
|---|---|---|
| 分辨率 | **768×1376**（1.0MP，ResolutionSelector 9:16 + megapixels 1.0）| **1568×896**（1.4MP） |
| 用途 | 口播主投 | 幕后揭秘 / 屏幕录制 / 流程透明 |
| 构图 | 人半身居中偏上，脸在上 1/3 | 录屏占 2/3，人脸小窗右下 |
| 封面 | 人脸特写 + 大字（≤8 字） | 录屏画面 + 标题条 |
| 字幕 | 见下方「字幕规范（2026-10-27 实测定板）」 | 同左 |
| BGM | -20dB，105 BPM 木吉他 + 轻鼓，2 秒淡出 | 同左 |

### 字幕规范（2026-10-27 实测定板，**取代旧的「48 号黄字白边」**）

> ⚠️ 旧规范「48 号黄字白边」已作废——实测在本片源上**读不出来**。
> 白衬衫亮度 174–180，黄字 #FFD700 对白衬衫对比度仅 **1.48:1**，
> 白边更让字和衬衫融成一片。WCAG 可读门槛 4.5:1，最好情况也只有 2.07:1。

**真正起作用的机制不是颜色，是深色粗描边**（剪映「描边字」同理）：

| 项 | 定板值 | 依据 |
|---|---|---|
| 分辨率基准 | **768×1376**（即 1080×1920 × 0.711/0.717） | 现有交付规格 |
| 正文字号 | **52 px** | 实测普惠体进距 0.745em，52px×12 字=421px、右余量 67px，14 字极限 496px 仍有 30px |
| 标题字号 | **80 px** | 开场钩子；副标题 38px |
| CTA 字号 | **62 px** | 结尾行动句 |
| 单行字数 | **7–12 字** | 用户 2026-10-27 定板；13 字整行比「11+2」好看，不折 |
| 标点 | **显示时去掉标点，逗号类换成半角空格，句末标点直接删** | 用户 2026-10-27 定板「会美观很多」；见下方说明 |
| 折行规则 | 只在标点处断，**绝不逐字硬切**；无标点的超长句查人工断点表 | `make_srt.py` 三级优先级 |
| 字色 | 白 `&H00FFFFFF` | 不用黄字——见上方实测 |
| 关键词色 | 暖金 #FFC24B `&H004BC2FF` + 放大 104% | 取自画面墙面色调，不打架 |
| 描边 | **5 px** 深棕 #080E14 `&H00140E08` | 字号每提一档描边收一号（7→6→5）；**下限 4px**，再细字边会渗进衬衫发虚 |
| 阴影 | 2 px，半透明 | 抬高字与底的分离感 |
| 底条 | **不用** | 底条会把白衬衫压成灰色，画面发脏（实测 S2_底条70 已弃） |
| 字体 | 正文 阿里巴巴普惠体 2.0 75 SemiBold；标题 115 Black | 免费商用、字形硬朗 |
| 安全区 | 上 y≥107 / 下 y≤1118 / 右 x≤661 / 左 x≥42 | 1080×1920 平台基准 ×0.711/0.717 |

> **字号微调的幅度门槛（2026-10-27 实测，重要）**：普惠体汉字实际进距只有 **0.745em**，
> 所以每 +2px 只涨 4.5%，肉眼看不出来。用户说「大一号」时，
> **必须一次 +4px（+9%）才有感知**。已走过两轮：44→48→52。
> 描边反向配套：字号每提一档，描边收 1px（7→6→5），否则视觉占比过粗显笨重。

### 标点处理（2026-10-27 用户定板）

**显示层去掉标点，逗号类换成半角空格，句末标点直接删。** 剪映字幕也是这个做法。

⚠️ **顺序是硬约束：内部全程保留标点，只在最后显示时抹掉。**
标点在这套流程里有四个用途——① 切分字幕条 ② 合并过短条 ③ 判断是否同句
④ 折行定位。先删标点，就无法判断「一拍就僵 / 发出去还怕朋友看见」该在哪断，
只能硬拆字，正是被明令禁止的「乱拆」。
实现：`make_srt.py` 里 `wrap()` 用带标点的文本折好行 → `display_text()` 再抹标点。

**为什么用半角空格而不是全角**：实测 libass 会**丢弃全角空格 U+3000**
（B「全角」与 C「删净」渲染结果几乎一致），只有半角空格真能留出 23px 间隙。
行末标点直接删——换行本身就是停顿，留个悬空空格会让居中排版的字偏左。

**平台安全区（2026-10-27 用户定板：相对就好，不用太严格）**：
参考线为 上 y≥107 / 下 y≤1118 / 右 x≤661 / 左 x≥42，但**不当作硬门槛**——
平台 UI 本身是半透明浮层，几像素互相让开是正常的，偶尔超一点不影响观感。
验收分三级（`04_验收工具/safe_zone_audit.py`）：

| 级别 | 门槛 | 处理 |
|---|---|---|
| 通过 | 越界 ≤4px | 测量误差量级，不记 |
| 可接受 | 越界 ≤16px（底部 ≤24px） | 记录但放行，可以发布 |
| 失败 | 超 16px（底部 24px） | 字会被真压住，必须改 |

**判断依据是「读不读得到」，不是「压不压线」**。v2 两套实测余量
上 +49 / 下 +30 / 左 +112 / 右 +45–49px，本来就在舒适区内。
坏味道是：往「越界 0px」死抠会把字号和位置都做小做死，反而不好看。

**质感分层（剪映等价做法）**：
- 开场 0–2.6s 钩子标题（上部空白区，弹入过冲 114%），标题里**必有一个金色锚点词**
- 正文条只做 `\fad(60,40)` 极轻淡入——观众在读字，字在动会打断阅读
- 全片花字只 8–9 处，挑痛点/数字/产品词；全篇都花等于没有花
- 结尾 CTA 单条（58px + 橙描边 + 112% 弹入），只留一条，多了会稀释真正的行动指令

尺寸切换技术方案见工作流①（`ResolutionSelector` 一个下拉），与珠珠链路共用同一套。

## 十二、镜头语言（2026-10-27 用户定板）

### 景别：只要微微一点动感
- **不要大运镜**。纯锁机位太死板，但推进拉远幅度一大就假、且会破坏跨段画幅一致。
- **标准做法**：段 1 开头 2.5 秒内极轻地退开约 2%（观感是"画面在轻轻松一口气"），
  之后全片彻底锁死。其余段一律固定机位。
- 幅度上限：不超过 3%。超过就变成"镜头在动"，注意力会跑到画面上。
- 实现位置：`summary` 里写运镜（服从度最高）+ `detailed` 不要重复写运镜，避免冲突。

### 结构：中间必须插一段屏幕录制
- 单条纯口播**必定单调**——2026-10-27 用户对 v5 的反馈就是"中规中矩，没有景别，有点单调"。
- **以后每条正片中间都插一段屏幕录制**（ComfyUI 工作流跑动 / 成片对比 / 素材上传界面），
  口播讲到"输入极简"或"二十分钟出片"时切过去，让画面有第二种信息。
- 屏幕录制段规格：竖屏 9:16 上下留口播画面、中间放录屏；或直接全屏录屏 + 人脸小窗。
- 切回口播时用硬切，不要叠化（叠化会显得像转场特效，短视频里不好看）。

## 十三、禁止项

### 业务
- 不承诺涨粉 / 爆款 / 销量数字
- 不说「AI 取代真人」（吓退潜在客户）
- 不展示未成交客户的素材
- 不贬低同行与真人主播
- 不用命令句（必须 / 记住 / 你不懂）

### 技术（与珠珠链路共用，H3 必守）
- 提示词禁止 no / not / never / without（会反向生成）；唯一例外：BGM 段 `no vocals or lyrics`、`kept low in the mix`
- `<Picture N>` 只出现在 `subject_definitions` 和 `retention_analysis`
- 视频端禁止加 turbo LoRA / Motion Repair / comfy kitchen attention / Sol-Attn
- **分段长度必须 `L ≡ 5 (mod 17)`**，且 **overlap 也必须 `≡ 5 (mod 17)`** → 只能取 22 / 39 / 56。
  22 是常规值，39 用于强衔接，56 慎用。`overlap < 相邻两段长度的较小值`。
  （2026-10-27 修正：旧版写"重叠只用 5 帧"是错的，5 不满足 5 mod 17 的余数要求，
  会走到独立段路径、接缝必跳）
- **必须用原生多窗口（`segmentConfig.count=N`）一次提交**，不能 `count=1` 交 N 次。
  `count=1` × N 是独立段，每段都从静帧重新起手，上一段的姿态/曝光/景别传不过去，
  提示词里写"接着上一段"完全无效。
- 只靠 `fully_preserved` 锁不住画面，四件套必须写死：内搭颜色 / 门襟开合 / 景别机距 / 亮度锚定句
