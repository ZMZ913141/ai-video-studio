# 字幕校验要点（make_srt.py 的配套验收）

SRT 出好后按下表自查，五项全过才算合格。

| 检查项 | 合格标准 | 为什么 |
|---|---|---|
| 折行 | **0 条硬断词** | 「换衣服/化妆」被切成「换衣/服化妆」观众会卡 |
| 行宽 | 每行 **7–12 字**（舒适区），硬上限 14 字 | 竖屏一屏放得下 14 字但太挤；7–12 字读着最舒服 |
| 最短显示 | ≥ 0.8s | 低于 0.8s 短视频里根本看不清 |
| 语速离散度 | 中位 ±1.5 字/s 内 | 全片语速忽快忽慢说明边界错了 |
| 首条起点 | ≤ 0.1s | 不能等第一个字说完才出字幕 |
| 末条终点 | ≥ 时长 − 1.0s | 不能提前消失 |
| ASR 校验 | 字数一致 | 字数不一致 = 文案与音频不符，先查文案 |

## 折行的三级优先级（2026-10-27 定板）

1. **有标点** → 挑一个让两行都 ≤12 字的标点位置断（`wrap()` 主路径）
2. **无标点但 >14 字**（必被播放器裁掉）→ 查 `MANUAL_BREAK` 登记的人工语义断点
3. **无标点且 ≤14 字** → **不折**。13 字一行比折成「11+2」好看得多

`MANUAL_BREAK` 只放超过物理上限的句子，断点必须落在词与词之间。
当前登记 1 条：`你是每次拍都得换衣服化妆找地方摆灯` → 12 字处断（换衣服化妆 | 找地方摆灯）。

## 常见失败与处理

- **ASR 字数不一致**：文案改过但音频没重录，或 TTS 漏读/多读。拿 `seg_report.py` 对时长。
- **某条语速 >8 或 <2.2**：DP 把两个意群塞进一条，或把一条劈开。
  调 `RATE_MIN/RATE_MAX` 或改文案标点（标点多切、标点少并）。
- **折行断词**：说明那条内部没有标点且超 14 字，且没登记 `MANUAL_BREAK`。
  改文案加个逗号最省事；不想改文案就往 `MANUAL_BREAK` 加一条语义断点。

## 为什么不用 ComfyUI 的 AILab_Qwen3ForcedAlign

该节点有上游 bug（`AILab_IterativeForcedAlign.py:256` 用了未定义变量
`transcript_text`，应为 `text`），一跑必 NameError。
**已在 2026-10-27 修好并备份原文件为 `.bak-20261027`**，但改 custom_node 需重启
ComfyUI 才生效。重启后的替代路线（更准，词级 30ms）：

```python
# LoadAudio → AILab_Qwen3ForcedAlign(text=文案, language="Chinese")
#   → 输出 WORD_TIMESTAMPS（"1.23-1.45: 字" 行文本）
# 拿到词级时间后，按标点切条即可，无需 DP
```

`AILab_Qwen3ASRSubtitle` 只给**句级**分组起止（句内要均分），
实测句中有停顿时边界会偏 0.3–0.7s，所以当前只拿它做字数校验。
