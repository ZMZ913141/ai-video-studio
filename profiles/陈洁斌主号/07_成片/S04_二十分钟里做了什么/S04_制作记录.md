## ★ 本套最大的技术发现：H3 会「把台词烧成画面字幕」，而解法在文案首句

**现象**：首版首句是「那二十分钟我到底做了什么」（标题式提问），
出片后画面里出现**烧进图像的白色字幕条**（不在字幕安全区，位置随机）。
四种提示词写法（明确禁止文字 / 描述无字环境 / 负向词 / 改构图）**全部无效**。

**判据（本套验证）**：

| 首句写法 | 结果 |
|---|---|
| 标题式提问（「那二十分钟我到底做了什么」） | ❌ 画面被烧字幕 |
| 已发生的具体动作/场景（「刚才那条片子，我把过程全录下来了」） | ✅ 干净 |

机理推测：H3 把「像标题一样的抽象提问」当成了画面内的字幕/板式元素。
只要你把首句写成**具体的、正在发生的动作**，它就没有可烧的东西。

**复验方式必须是正式分辨率**：①`PILOT=1`（864×1536，约 3 分钟）；
②0.25MP / 0.5MP 低分辨率样片**看不到**烧字（文字在降采样里糊掉了），
所以低分辨率验出来的「干净」**不构成证据**。这一条已写回 SKILL.md。

## ★ 本套踩到的第二个坑：TTS 重跑会让整体电平漂 3.7 dB

| 文件 | 语音 RMS | 峰值 |
|---|---|---|
| S01 | −28.5 | −7.1 |
| S02 | −27.6 | −4.1 |
| S03 | −26.8 | −2.5 |
| S04 被拒版（36.9s） | −27.8 | −5.3 |
| **S04 定板（36.0s）** | **−30.5** | **−9.0** |

同一套文案、同一次 TTS 重跑，电平整整低了 3.7 dB。
后果不是「小声一点」——`audio_check.py` 算出
`停顿处 −42.3 / 人声 −30.5 = 差 −11.8 dB`，直接判 ❌「基本无配乐」，
因为人声变轻后配乐相对靠前，配方比例全乱了。

**修法**：`mix_bgm.py` 现在默认开 `VO_NORM`，混音前先量人声 RMS，
按 `VO_TARGET=−26.8`（S03 定板）算增益（钳 ±8 dB），
并在链路末端挂 `alimiter=0.95` 防削波。实测施加 **+4.0 dB**，
交付人声 −26.8 dBFS，与前三条一致。定板 mp3 也同步归一
（原电平文件备份在 `08_过程/S04_二十分钟里做了什么/S04_音频_原始电平_-30.5dBFS.mp3`）。

## ★ 本套第三次返工：整片响度离平台标准差 10–12 LU（用户反馈「尾音太轻、没字幕听不清」）

`audio_check` 判「无配乐」那次，其实暴露了更大的问题——不只 S04，是**四条片全系列都太轻**：

| 片 | LUFS | LRA | 峰值 |
|---|---|---|---|
| S01 | −28.8 | 4.6 | −9.7 |
| S02 | −27.1 | 7.9 | −6.8 |
| S03 | −26.4 | 8.9 | −5.9 |
| S04（v1） | −25.8 | 6.0 | −8.0 |

短视频平台通用标准是 **−14～−16 LUFS**，我们低了 10～12 LU。用户这次听不清，
本质是整体电平离标准太远，再叠上句尾衰减 5～9 dB（cue13/15/18 都是 −9 dB），
句尾的字就基本听不见了。

**修法（v2）**：`mix_bgm.py` 在 VO_NORM 之后挂两遍 `loudnorm`（测量遍 + 应用遍），
整片拉到 **−16.0 LUFS / Peak −1.5 dBFS**（无削波）。同时：
- 人声侧加 `equalizer f=250 g=−1.5`（压一点鼻音）、`f=3200 g=+2.5`（提一点齿音清晰度）、
  温和 `acompressor`（threshold −30 / ratio 2 / attack 15 / release 250）把句尾衰减收平；
- 句尾衰减平均从 −3.3 dB 收到 −1.4 dB，最差的 cue15 从 **−9.3 dB 收到 −5.0 dB**。
- 去掉了原先的 `alimiter=0.95`（两遍 loudnorm 已不削波，硬限幅反而压扁动态）。

**涟漪效应（重要）**：响度提高后，句间衰减尾音变响，`srt_sync_audit` 把尾音当成了下一句起音，
cue12「差半拍你就看出假了」报 +0.400s 错位。实测起音能量在 20.00s（−32.7→−14.6 跳变），
字幕写的 20.08s，按真值把 cue12 起点改成 `00:00:20,000`。改后 18/18 全过（±0.35s 内）。

### 关于 corr首帧 −0.104 的判断（未被判为缺陷）

S03 就留下过同一条残余漂移（−0.06），当时的结论是「来自 H3 真实光照/表情，后期补不了」。
本套先量了不依赖该指标的物理量再下结论：
八帧拼图里发宽/肩宽/头顶位置一致，脸均只降 5.1、p99 只涨 11.9，spark 完全平。
**所以这是色调曲线随时间的轻微对比度上抬，不是身份/景别漂移。**
工具那句「❌ 后段偏离首帧（corr 掉 −0.104）」是启发式告警，本套判为可接受，理由记在这里备查。

## 与 S01–S03 的差异

1. **第一次「报账」而不是「讲道理」**：前三条都在讲价值主张，这条直接拆时间成本。
   骨架是 5/10/5 三个数字，所以三个时间词（前五分钟/中间十分钟/最后五分钟）必须上花字。
2. **第一次用 864×1536（1.266MP）**：S03 是 768×1376 与 896×1568 并存，
   本套直接定在中间档，段数 7、MAXLEN 141，切点 6/6 全落停顿。
3. **第一次在混音阶段做响度对齐**：因为 TTS 电平漂了 3.7 dB（见上）。
